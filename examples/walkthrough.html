@knsdomains/sdk-tx by example

This page walks through every operation the package builds: a registration, a profile change, the primary name, a listing and a purchase, a transfer, a subdomain, a multisig round trip, and following the chain. Each one shows the code, what it answers with, and the point where the wallet asks the person to sign.

Nothing on this page runs. Every operation here spends coins and needs a signature, so a page that ran them would need your wallet and your money. Read it beside the package's README and copy what you need.

The figures are the testnet-10 deployment's: a name of five code points or more costs 35 KAS, four cost 525, three 2,100, and one or two 4,200. Every registration locks three 0.6 KAS deposits in covenant outputs and sets aside one 0.2 KAS fee allowance, so a 35 KAS name needs 37 KAS in the wallet. A spend of a name you hold (a transfer, a profile change, the primary flag, a listing, a cancel) pays its network fee, about 0.013 to 0.016 KAS, from the wallet; the name's deposit is never spent on it. A buy pays the price, and a subdomain mint locks 1.8 KAS of deposits and pays the 1 KAS subdomain fee and about 0.03 KAS of network fee, from the wallet. A sompi is 1e-8 KAS.

What you wire up

The package holds no key. You give it the read client, the wasm module, a node URL and a wallet. The module connects to the node itself for every operation that reaches the chain, and it verifies every signature the wallet returns against its own hash before anything is sent.

probeSigner broadcasts nothing. It asks the wallet to sign a real gap input it does not own and a coin of its own, and reports whether the wallet signed the foreign input and whether its hash is the module's.

Register a name

A registration is one transaction: it splits the gap covering the name, mints the name's claim and its state, locks three 0.6 KAS deposits, and pays the fee to the registry's fee address. The wallet is asked once. There is no salt to keep and nothing to resume: until it is accepted nothing happened, and once it is the name is held. The protocol accepts front-running, so whoever's registration is accepted first holds the name.

Plan, show, submit

Every spend of a name you hold is two steps. plan… reads the name's current state from the tracker, has the module confirm it on the node, checks the product rules and answers what the wallet will be asked, with nothing signed. submit hands that to the module. The one-step calls (transfer, list, …) are the two in a row.

A plan built on a state the chain has since moved past is refused by the module, so build one close to the prompt. Every refusal before the prompt is a KnsTxError with a code.

Change the profile

A name points at its profile by the sha256 of the document's bytes, as a bafkrei… CID. The document itself is pinned with the tracker (POST /v1/pin) or anywhere that serves the same bytes; the chain holds the digest alone.

The primary name

An address shows the name its holder flagged. The flag is on chain, in the name's state, so setting it is a transaction. With several flagged names, readers show the one whose output moved last; the plan says how many others stay flagged.

List, cancel, buy

A listing moves the name into a listing contract at a fixed price, at least 0.2 KAS; while listed it cannot be transferred, given subdomains or a new profile. A buyer pays the seller in the same transaction and gets the name with an empty profile, unless the buyer sets one.

A marketplace can write its fee into a listing: an address and a rate of 1 to 1000 basis points of the price, which the seller agrees to by signing the listing. Every purchase, through any front end, then pays the fee to that address and the rest to the seller, or the contract refuses it. A fee under 0.2 KAS is left out, and the plan says so. Testnet-10 lineage 4d10952e…, the one the packages carry, runs it.

Hand a name over

A recipient is an address. Bare hex is refused, because a key and a multisig's script hash look the same and a name sent to a key nobody holds is gone. The primary flag stays only for a transfer to yourself.

Mint a subdomain

A subdomain is a name of its own, minted by the holder of its parent and given to anyone. The parent's holder locks its deposits, 1.8 KAS, and pays the 1 KAS subdomain fee to the registry's fee address; once minted it cannot be taken back.

A multisig holder

A name an m-of-n Schnorr multisig holds is spent in three steps: the module builds one fixed transaction and answers a signing file (the CLI's --multisig file), each co-signer adds a signature over the hashes in it, and finishMultisig puts m signatures into every coin's witness, checks every input in the script engine, and sends it. The multisig spends one of its own coins beside the name, so it must hold one.

Follow the chain

A follower answers the DAA score now, waits for a target, and says where a transaction was accepted. Three sources: a JSON wRPC connection of the package's own, a rusty-kaspa wasm RpcClient, or a Kaspa REST API, which is the one that answers by txid after the fact.

When something refuses

Every refusal before the prompt costs nothing. A KnsTxError carries a code and the operation in op.

Code When
lost-race somebody spent the gap first
wallet-declined the wallet declined, or signed nothing for a requested input
signature-invalid the wallet returned a signature the module refuses
insufficient-funds the wallet holds too little
deployment the module's values are another registry's
not-registered, hint-refuted the name is not held, or the tracker's record did not check out on the chain
entrypoint-disabled the deployment's emergency deny list switched this entrypoint off
node-unreachable, registration-closed the node did not answer; open registration has not started on this deployment

@knsdomains/sdk-tx builds, signs through a wallet and sends; @knsdomains/sdk reads. Their READMEs are the reference for every call.
